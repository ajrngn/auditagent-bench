# CLAUDE.md — SOX Control Evaluation Benchmark ("AuditAgent Bench")

## Project Overview

A public benchmark evaluating how well LLMs perform internal-control (SOX 404) assessment tasks — the internal audit analog to financial-statement benchmarks like AuditBench and FinVerBench, which cover statement/numerical error detection but not control design or operating-effectiveness evaluation.

**Deliverables (in dependency order):**
1. Labeled dataset of internal control scenarios (JSONL, versioned in GCS)
2. Eval harness (prompting, parsing, scoring across multiple model vendors)
3. Published results + analysis (audit-agent.ca, GitHub/HuggingFace, possible ISACA article)

**Differentiation:** existing benchmarks test error detection in financial statements. This one tests control evaluation — deficiency classification, control design assessment, clean/dirty discrimination, and standards citation. No existing benchmark uses SEC Section 404 material weakness disclosures as labeled data.

## Hard Constraints

- **Browser/cloud only.** Developer works on a locked-down corporate laptop. No local servers, no desktop installs, no localhost anything. Everything runs in Google Colab, Apps Script, or GCP-hosted services.
- **Public data only.** No GFL Environmental data, ever. All dataset content must come from public sources (SEC EDGAR) or be synthetically authored.
- **Hand-verified labels.** LLMs may draft candidate scenarios or labels, but every ground-truth label in the released dataset must be human-reviewed before inclusion. Never mark a generated label as verified.

## Architecture

```
EDGAR APIs ──> Colab notebook (fetch) ──> gcs://<bucket>/raw/          (10-K HTML)
                Colab notebook (extract) ──> gcs://<bucket>/processed/  (Item 9A JSONL)
                Google Sheet (labeling UI, Apps Script sync)
                Colab notebook (build) ──> gcs://<bucket>/benchmark/    (versioned dataset)
                Colab notebook (eval harness) ──> results/ + analysis notebooks
```

- **GCS bucket prefixes:** `raw/`, `processed/`, `benchmark/`, `results/`. Benchmark releases are immutable and versioned (`benchmark/v0.1/`, `benchmark/v0.2/`...). Never overwrite a released version.
- **Model access:** Gemini via Vertex AI; Claude via first-party Anthropic API; GPT via OpenAI API; open-source (Llama) via Vertex Model Garden. Cross-vendor coverage is non-negotiable for credibility.
- **Prefer Batch APIs** for eval runs — nothing is latency-sensitive; batch pricing roughly halves cost.
- **Labeling UI is a Google Sheet.** Pipeline writes candidates to the sheet; human reviews in browser; Apps Script writes validated rows back to GCS. Do not build a custom labeling web app.

## Data Sources

| Source | Use | Access |
|---|---|---|
| EDGAR full-text search (`efts.sec.gov`) | Find 10-Ks disclosing material weaknesses | Free, no key; query "material weakness", form type 10-K |
| EDGAR submissions API (`data.sec.gov`) | Filing indexes, fetch 10-K HTML | Free, no key; **must set a descriptive User-Agent header per SEC policy, max ~10 req/s** |
| Item 9A extraction | Core text for Tasks A & C | BeautifulSoup over filing HTML |
| Synthetic scenarios | Task B (control design) | Hand-authored + LLM-drafted variants, human-verified |
| COSO 2013, PCAOB AS 2201 | Label taxonomy & severity definitions | Reference only — do not reproduce framework text verbatim in the dataset |

Target for v1: ~500 filings (~250 with material weaknesses, ~250 clean), ~300–400 final benchmark items.

## Task Definitions

- **Task A — Deficiency classification:** disclosed weakness → severity (deficiency / significant deficiency / material weakness) + COSO component. Labels derived from disclosure itself.
- **Task B — Control design evaluation:** process narrative + control description → designed effectively? If not, identify the gap (SoD, precision, evidence, timeliness...). Synthetic, hand-labeled.
- **Task C — Clean/dirty discrimination:** mixed clean and deficient Item 9A text → flag correctly. **False-positive rate on clean items is the headline metric** (FinVerBench found 95–100% FP rates on clean statements for most models — test whether this holds for controls).
- **Task D — Standards citation:** identified deficiency → correct COSO principle / PCAOB standard citation.

## Coding Conventions

- **Python in Colab notebooks**, one notebook per pipeline stage: `01_edgar_fetch`, `02_extract_item9a`, `03_labeling_sync`, `04_build_benchmark`, `05_eval_harness`, `06_analysis`.
- Notebooks must be **idempotent and resumable** — check GCS for existing outputs before re-fetching/re-processing; long EDGAR pulls will hit interruptions.
- All records are **JSONL with an explicit schema** (`schemas/`); include `source_url`, `accession_number`, `cik`, `fiscal_year`, `label`, `label_source` (`disclosure` | `human` | `llm_draft_human_verified`) on every item.
- **Structured outputs from models:** request JSON, strip markdown fences before parsing, wrap parsing in try/except, log raw response on failure. Never regex-parse free text when JSON output is available.
- Pin model versions with full model strings (e.g. `claude-sonnet-4-6`, not "latest") in eval configs; record model string + date in every results file.
- Store API keys in Colab Secrets, never in notebook cells or GCS.
- `pip install` in Colab: fine as-is (no `--break-system-packages` needed in Colab).

## Eval Harness Rules

- One standardized prompt template per task, versioned alongside the dataset. Prompt changes = new results version; never compare results across prompt versions silently.
- Metrics: per-task accuracy, severity confusion matrix (Task A), FP rate on clean items (Task C), citation precision (Task D).
- Run each model on the full item set; no sampling shortcuts in released results.
- Log every raw model response to `results/<run_id>/raw/` before scoring — scoring bugs are recoverable, lost responses are not.

## Contamination Policy

EDGAR filings are in every model's training data. Mitigations (document all of them in the write-up):
1. Prioritize 2025–2026 filings (post-cutoff for most evaluated models).
2. Maintain a paraphrased subset of disclosure items to separate memorization from reasoning; report both scores.
3. Task B synthetic items are contamination-free by construction — treat them as the reasoning control group.
